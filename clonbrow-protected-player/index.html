Important limits

  • A client HTML page is public. Never embed a master API key or database password in it.
  • A unique name alone does not prove identity. The server needs enrollment, authentication, rate limits and key revocation.
  • A play URL is laptop independent only if the server stores and serves the project.
  • A browser cannot create a desktop folder and start Terminal. The user can download a protected ZIP and unlock it with a compatible desktop extractor.
  • The API must allow this page's publishing origin in CORS settings.

Architecture: what runs where

Portal: this HTML file, hosted as a static site; it has no privileged secrets.

API: an HTTPS service validates users and node claims, issues/revokes scoped keys, accepts archives and returns project status/links.

Database: persistent shared storage for users, claims, API key hashes, projects, permissions and audit events. Browser localStorage or a laptop file cannot enforce single-use claims across devices.

Storage and runner: private object storage plus isolated build/hosting workers. Never execute uploaded files on the API host with unrestricted access.

Protected download: produce a separately encrypted ZIP. Hosted playback is a server copy with its own access rules; do not retain the user's package password as plaintext.

Required endpoints and response shapes
GET  /api/v1/health
  -> {"status":"ok","service":"clonbrow-api","version":"1"}

POST /api/v1/nodes/claim
  {"enrollmentId":"single-use-value","label":"My laptop"}
  -> 201 {"nodeId":"node_…","apiKey":"cb_live_…"}
  Invalid, expired or used ID -> 409 {"error":"enrollment_unavailable"}

POST /api/v1/projects  (multipart/form-data, Bearer API key)
  fields: title, archive (ZIP), packagePassword
  -> 202 {"projectId":"project_…","state":"building"}

GET  /api/v1/projects/{projectId}
  -> {"projectId":"project_…","state":"ready","playUrl":"https://play.example/…"}

GET  /api/v1/projects/{projectId}/package  (Bearer API key)
  -> 200 application/zip, password protected

POST /api/v1/api-keys/{keyId}/revoke
  -> 204

GET  /api/v1/nodes/me/projects
  -> {"items":[{"projectId":"…","title":"…","state":"ready"}]}

If your deployed API uses other route names, adapt this page's script or make the service implement this contract.

Database tables and uniqueness rules
users:        id, normalized_name UNIQUE, created_at, disabled_at
nodes:        id, owner_user_id, label, created_at, revoked_at
node_claims:  id, claim_hash UNIQUE, expires_at, claimed_at, claimed_by
api_keys:     id, node_id, key_hash UNIQUE, prefix, scopes, created_at, revoked_at
projects:     id, owner_user_id, node_id, title, state, storage_key, play_url
project_jobs: id, project_id, state, error_code, started_at, finished_at
audit_events: id, actor_id, action, object_id, created_at, safe_metadata

Use database constraints and transactions for name uniqueness and single-use claim redemption. Store hashes of enrollment IDs and API keys, not their plaintext. Return a new API key once; support rotation and revocation. Add quotas and upload limits.

Security, passwords and browser limits
  • Use HTTPS and check ownership on every project operation. Allow only the portal origin via CORS.
  • Send keys in Authorization headers, never URLs, HTML source or logs. This page keeps a key in memory only; reload clears it.
  • Use a password hashing function made for login passwords (such as Argon2id). Encrypt archive downloads using a reviewed authenticated-encryption format and password-based key derivation; generate a fresh random salt and nonce per package.
  • Never log the package password or full key. Apply rate limits, archive path traversal checks, file size/type limits and safe build isolation.
  • A browser cannot run terminal commands or guarantee files are extracted into a desktop folder. A one-click installer requires a separately built and signed desktop app.
Deploy and connect checklist
  1. Deploy the API, database, private object storage and isolated project hosting worker.
  2. Implement the contract above; set HTTPS, CORS, upload limits, quotas and backups.
  3. Have an administrator issue short-lived, single-use enrollment IDs.
  4. Publish this HTML file. Set the API URL, check health and claim a node. Save the returned key securely.
  5. Upload a web project ZIP. Wait for state ready, then use the returned play URL. Download the protected package separately if needed.

Until those backend services are deployed, the portal shows connection errors. Publishing only this HTML does not create the backend or keep it running.
